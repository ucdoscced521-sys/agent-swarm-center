## 4. 结论

**已排除的原因**

- ❌ 不是 stdin（关掉无效）
- ❌ 不是会话抢占（清掉继承的 `CODEBUDDY_SESSION_ID` 无效）
- ❌ 不是 CLI 坏了（`--help` / `--version` 正常，bundle 加载正常，配置全通）

**剩余原因（证据支持的判断）**

该 CLI 被设计为**由桌面端以 `--serve` / `--prewarm` 托管启动**（见 `bin/codebuddy` 内注释），本身是"宿主进程"形态。在被当作子进程、以管道 stdio 启动时，`-p` 拿不到执行回合：既不报错也不退出，只是注册一个无端点的 `interactive` 会话后空转。

**因此**：**`-p` 在"WorkBuddy 子进程"语境下不执行一次性回合。** 从 WorkBuddy 会话内部验证这条路本质上是不可能的（等于 WorkBuddy 套 WorkBuddy）。

**唯一剩下的决定性变量**：**控制台 stdio vs 管道 stdio**。在**外部真实控制台**里跑（双击 `bridge-test.cmd` 或普通 CMD 窗口），stdio 是 console 而非 pipe——这是与本次全部失败尝试唯一的差异。

## 5. 下一步（二选一）

**方案 A：外部控制台验证（推荐，成本最低）**

在外部 CMD 窗口/双击运行 `agent-swarm/skills/agent-swarm/scripts/bridge-test.cmd`。
- 输出出现 `BRIDGE_OK` → B3-CB 成立，正式启用
- 两文件均空 → 保持文件总线兜底

**方案 B：改用会话 HTTP 端点（若 A 失败）**

`--serve`（REST + Web UI + ACP over HTTP SSE）或 `--acp`（stdio）是显式为程序化驱动设计的接口，比 `-p` 更适合做常驻桥：

```bash
node <cbc> --serve --port <free> --auth password
# 从 sessions/<pid>.json 读回 url 与端口，通过该端点投递任务、回收判定
```

⚠️ **安全红线：绝不用 `--auth none`** —— 帮助原文：*"lets any local process execute commands and read/write files through the server"*。
该通道**尚未实测**，仅作为备选方向记录。

**兜底（当前生效）**：`.swarm/bus/` 文件总线。零依赖、离线可读、B3 挂三次自动降级到它——功能不受影响，只是跨宿主慢一点。

## 6. 顺带挖到的能力（对架构是净增益）

WorkBuddy CLI v2.137.1 的完整无头参数表，与我们的架构设计几乎逐条对应：

| 架构需求 | 参数 |
|---|---|
| 无头单次执行 | `-p/--print` |
| 结论结构化 | `--output-format json` + **`--json-schema`**（可把"首行 PASS/FAIL"升级为 schema 强校验）|
| **主脑能力剥夺** | `--tools ""` / `--disallowedTools "Bash,Edit,Write"` ← "不写代码"从自律变**物理不可为** |
| 注入角色提示词 | `--system-prompt-file` / `--append-system-prompt` |
| **JSON 定义多角色** | `--agents '{"name":{...}}'` |
| **原生真并行** | **`--swarm`**（teammates 独立进程）+ `--bg` + `-w/--worktree`（原生 git worktree）|
| 会话续跑 | `--session-id` / `-c` / `-r` / `--fork-session` |
| 预算 | `--max-turns` / `--effort` / `--autocompact` |
| 常驻服务 | `--serve` / `--acp` |
| 权限 | `-y`、`--permission-mode`、`--subagent-permission-mode` |

**`--swarm` 最值钱**——官方原生支持"teammates 跑成独立进程"，我们不必自建进程池。

## 7. 复现步骤

```powershell
$node = "C:\Users\lxjhudan\.workbuddy\binaries\node\versions\22.22.2-3\node.exe"
$cbc  = "D:\WorkBuddy\resources\app.asar.unpacked\cli\bin\codebuddy"

# 1) 入口自检（应打印 2.137.1）
& $node $cbc --version

# 2) 无头往返（把输出落到工作区内，避免权限问题）
"" | & $node $cbc -p "reply with exactly: BRIDGE_OK" --output-format json | Set-Content .\out.json
Get-Content .\out.json
```

**注意**：步骤 2 在 WorkBuddy 会话内部预期会**长时间无输出且不退出**（本次已实测 3 次）。它需要在**外部控制台**运行才有意义；若在内部跑，请自行在数十秒后终止进程（否则会留下 ~300MB 的空转进程）。
