# 04 · 优化路线与验证计划

> 触发：跨宿主桥（Codex → WorkBuddy）实测三次不通。
> 本文回答"接下来该怎么优化"，并给出可验收的四步计划。

---

## 0. 结论先行

**三句话**

1. **桥不修了。** 跨宿主调用是**手段不是目的**——你要的是"一句话进去、真并行多子智能体、闭环自主推进"。这件事**单宿主内今天就成立**，不需要跨宿主。
2. **更该解决的问题不是桥，而是"整套东西一次都没真跑过"。** 目前设计文档约 40KB，但**零次端到端实跑**。这是当前最大的风险，比桥大得多。
3. **所以优化方向是：冻结设计，转入验证。** 先跑通最小闭环拿到实测反馈，再按反馈修设计——而不是继续在纸面上加东西。

---

## 1. 重新定义问题：我们一直在优化手段

| | 手段 | 目的 |
|---|---|---|
| 你真正要的 | — | 一句话任务 → 自主拆解 → **真并行**子智能体 → 状态回流 → 闭环推进到交付 |
| 跨宿主调用 | ✅ 是手段之一 | ❌ 不是目的 |
| 自建 Loop Engine 进程池 | ✅ 是手段之一 | ❌ 不是目的 |

**关键事实（因这轮排查才明确）**：

- **WorkBuddy 宿主内已有原生真并行**：`TeamCreate` + `Agent` spawn + `SendMessage`。我写的那 7 个角色的提示词，用的就是这个机制。
- **Codex 宿主内也有原生真并行**：subagents + `codex exec` + `codex agents` + `codex queue`。
- **跨宿主只在"某能力只有另一宿主才有"时才需要**，而这种情况有 `.swarm/bus/` 文件总线兜底（零依赖、已可用）。

**推论**：跨宿主通道不通，**不影响任何一个核心目标的达成**。它只影响"跨宿主那一跳慢一点"。

---

## 2. 三条优化路线

### 路线 A：冻结设计 → 转验证 → 按实测修设计 ⭐推荐

| 项 | 说明 |
|---|---|
| 做什么 | 停止加设计。用**最小任务**跑通一次完整闭环（派单 → 执行 → 出 verdict → 判定 → 升级/收敛），拿到真实数据 |
| 理由 | 现在所有设计都是"逻辑上应该成立"。真正会暴露问题的是实跑：prompt 是否被遵守、verdict 是否能解析、子智能体是否真并行、异常能否兜住。这些都是**只能实测才知道**的事 |
| 预期效果 | 半天内知道"这套东西到底能不能用"；把后续优化从"猜"变成"看着数据改" |
| 成本 | 极低（小模型 + 小任务，约 10–30 credits） |

### 路线 B：先吃透 WorkBuddy CLI 的原生能力（与 A 并行）

| 项 | 说明 |
|---|---|
| 做什么 | 摸清 `--swarm`（teammates 独立进程）、`--bg`、`-w/--worktree`、`--json-schema`、`--disallowedTools` 的真实行为 |
| 理由 | 这轮白捡到一个事实：**官方原生已经实现了我们准备自建的东西**。`--swarm` = 真并行，`--worktree` = 隔离，`--json-schema` = 强校验判定，`--disallowedTools` = 能力剥夺。用官方的，省掉自己维护 |
| 预期效果 | 可能整层"自建 Loop Engine 并发层"可以删掉，直接站在官方能力上 |
| 成本 | 低，但**有前置依赖**：需在外部控制台验证（`-p` 类调用在我这儿跑不通） |

### 路线 C：继续修跨宿主桥 ❌不推荐

| 项 | 说明 |
|---|---|
| 做什么 | 继续试 `-p`、改用 `--serve` + 会话 HTTP 端点 |
| 理由（不推荐） | 已证明是**环境限制**不是能力问题——我无法脱离 WorkBuddy 进程树。投入产出比最差 |
| 唯一例外 | 如果你想让我用 `--serve` 再试一次，成本也就一次调用；但**别把它当阻塞项** |

**决策建议**：**A 为主线，B 作为 A 的收益放大器，C 降级为"有空再说"。**

## 3. 四步验证计划（每步都有完成标准 + 停止条件）

> 原则：**每步都要能独立验收**；跑不过就停，不在坏地基上加东西。

### Step 1 · 最小闭环（最重要，先做这个）

- **任务**：一个**故意做小**的真实任务（例：让 builder 写一个 20 行的脚本 + 一个测试，verifier 独立复核）
- **范围**：1 个主脑 + 1 个 builder + 1 个 verifier。**不要 7 个角色全上**
- **完成标准**
  1. `inbox/<id>.task.md` 任务说明书生成且自包含
  2. builder 产出交付物 + `outbox/<id>.verdict.md`，首行格式合规
  3. 主脑**只读首行**就完成判定（能证明没读正文）
  4. verifier 独立复核，且与 builder 判定**可能不一致**（说明真的独立）
- **停止条件**：任一项做不到 → 停下来修那一个，**不往下走**
- **预期耗时**：30–60 分钟

### Step 2 · 真并行（命门）

- **任务**：3 个**无依赖**子任务同时派给 3 个 builder
- **完成标准**（沿用协议里的 M1–M6）
  - M1 并发度 = Σ任务时长 ÷ 阶段墙钟 **≥ 2.5**
  - M2 `events.jsonl` 里 ≥2 个 `task.start` **时段有交集**
  - M3 同一时刻 ≥3 个子进程
  - M4 子智能体 prompt 里**不含**其他子智能体的产出正文
  - M5 两子智能体同写一文件 **被 worktree 隔离拦住**，零互覆
  - M6 每个子智能体有独立 session/进程标识
- **红队反测**：把某个子智能体换成**串行假实现**，Gate **必须报 FAIL**。若通过 → 判定伪协作，架构作废重做
- **预期耗时**：1–2 小时。**这步是整件事的命门。**

### Step 3 · 判定硬化（把协议交给机器强制）

- **动作**：用 `--json-schema` 替代"首行文本 + 正则"
  ```json
  {"type":"object",
   "properties":{"verdict":{"enum":["PASS","FAIL","BLOCKED"]},
                 "evidence":{"type":"array","minItems":1}},
   "required":["verdict","evidence"]}
  ```
- **完成标准**：注入一个"有判定无证据"的返回 → **必须被 schema 挡掉**，而不是靠我们事后校验
- **预期效果**：从根上消灭假 PASS 和格式不合，删除一堆防御性解析代码

### Step 4 · 主脑边界硬化（"非伪协作"的最后一道锁）

- **动作**：用 `--disallowedTools "Bash,Edit,Write"` 或 `--tools ""` 限制主脑
- **完成标准**：主脑**尝试写文件时报错**（而不是"它很乖地没写"）
- **预期效果**：参考图里那句"主 Agent 只调度不干活"，从**提示词自律**升级为**物理不可为**

## 4. 当前最大的风险（必须先说）

| 风险 | 表现 | 处置 |
|---|---|---|
| **纸面完备、实战未验** | 设计文档 40KB、协议完整、头像齐全、双宿主已注册 —— 但**一次都没真跑过** | Step 1 立刻消除 |
| **过度设计** | Loop Engine 并发层可能被 `--swarm` 原生替代；`--worktree` 也是原生 | 路线 B 校准，能删就删 |
| **成本失控** | 多智能体长时循环容易烧 credits | 验证期用假 worker / 小模型；先定预算红线（已有：单任务 20min、单阶段 3 轮） |
| **未验证项被当结论用** | 桥、`--swarm`、HTTP 端点都还没实测 | 文档里明确标注"未验证"，不许当既定事实 |

---

## 5. 现在就能做的第一件事（30 分钟内可完成）

**跑 Step 1 的最小闭环，但用"零成本"方式做**：

1. 建 `.swarm/` 骨架（1 分钟）
2. 派一个真实但极小的任务（例：写一个读 JSON 并输出字段数的 20 行脚本）
3. 用**假 worker**（一个直接写 verdict 的脚本）先验证**回流链路与判定逻辑**通不通 —— 不烧 credits
4. 链路通了，再换真智能体跑第二次

**为什么先假后真**：把"链路问题"和"模型行为问题"分开定位。混在一起跑，失败了你不知道是协议错还是模型没遵守。

---

## 6. 一句话交底

**这套东西的设计已经够多了，缺的是"跑一次"。**

桥、`--swarm`、HTTP 端点都是可以以后再补的**增量**；
而"端到端到底能不能跑"是**前置条件** —— 它不成立，上面所有东西都只是文档。

**建议：这周别再加功能，先把 Step 1 + Step 2 跑通。** 跑通了，我们再谈跨宿主、谈长时自主、谈 7 个角色全上。
