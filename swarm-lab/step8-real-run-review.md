## 2. 🔴 A 类：我的协议本身的缺陷（5 个，必须修）

### A1. 事件流格式未被遵守 → **并发度指标完全失效**（最严重）

- **协议写的**（`protocol.md §3`）：`{"ts":"...","e":"task.start","task":"T-003","agent":"...","pid":24118}`
- **真实用的**（`.swarm/state/events.jsonl`，95/95 行）：`{"ts":"…","phase":0,"event":"project_init","task":"T-000","actor":"team-lead","detail":"…"}`
- **更糟**：第 2 行明确写着「**ts 为合成阶梯**（自 20260925 2355 起约每行 +1 分钟），**非逐分钟真实时间**」

**后果**：Step 2 验过的 **M1–M6 六个并发度指标，在真实运行里一个都算不出来** —— 字段名不对，时间戳还是编的。
**这是"验证成果与协议脱节"**：我验了指标有区分力（M1 2.91 vs 0.99），但协议没规定能算出指标的字段格式，团队自然发明了自己的。

**修**：协议把事件格式写成**强制契约**（字段名、必填项），并**禁止合成时间戳**（`ts` 必须 ISO 8601 真实时刻）；`metrics.mjs` 同步适配。

### A2. "厂商异源"是不可达的硬要求 → 团队被迫静默降级

- **协议写的**：「`verifier-independent` 必须与 `builder-core` **使用不同厂商的模型**；同源验收视为未验收」
- **真实情况**：环境只有 `deepseek-v4.1-flash` → 10 份复核全部是「代理实例异源」

**后果**：按协议字面，**这轮 10 份复核全部"视为未验收"**——等于全轮验收无效。团队只能自行降级并在 handoff 里标注。
**协议提了一个做不到的要求，等于没有要求。**

**修**：改成**分级异源**并强制标注：

| 级别 | 条件 | 效力 |
|---|---|---|
| L3 完全异源 | 不同厂商模型 | 达标 |
| L2 强异源 | 不同会话 + 不同 agent 身份 + **不同证据文件** + 不看对方结论 | 有条件达标（须在 handoff 标注）|
| L1 弱异源 | 仅不同 agent 身份 | **视为未验收** |

### A3. 说明书模板用相对路径 → **必然产生双调度根**

- **协议写的**（`protocol.md §1`）：派单落 `.swarm/bus/inbox/<task-id>.task.md`（**相对路径**）
- **产出人 cwd = 代码仓库** `E:\codex\...\personal-workbench`（**不是工作区**）→ 它们在仓库内**新建了第二个 `.swarm/`** → 主脑过闸全部报 `no_verdict`
- 团队自己发现、自己修（D-020，`robocopy /E` 合并 + 契约加硬规矩），**但协议原文没写**
- 我的审计 A9 显示后来 11 份说明书都合规了——**因为团队自己补了规矩，不是协议给的**

**修**：`protocol.md §1` 直接写明「SWARM_DIR 必须写**绝对路径**；只有 `evidence` 数组内部用相对短路径（闸门会 `path.join(SWARM_DIR, p)`）」。

### A4. `metrics.tests` 的 `maxLength: 32` 太紧 + 提示词没强调"短标识"

- **真实事故**（D-020 连带）：复核官把结论说明写进 `metrics.tests`，长度 **39/61** 字符 → `schema_violation` → 重发

**修**：放宽到 64，并在提示词里给**正反例**（✅`"88/88"` / ❌`"全部通过，但有一个边界未覆盖"`）。

### A5. 协议没规定临时产物与清理

- 真实运行自创 `evidence/_scratch/`（数百个临时文件），`_repo-mirror/`（双根事故残留）**至今留在 `.swarm/` 里**

**修**：协议加「临时产物一律落 `_scratch/`；收口时清理或写明归档理由」。
